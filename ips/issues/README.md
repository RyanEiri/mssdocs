# Issues (optional module)

A publication's **issues as PDFs**, with the text read page by page for search. Design, reasons and the plan for testing the search: `docs/mssdocs-issues-design.md` in the fleet repository. The module is built in four stages, all done: J1 (the data, the PDF store, the text extraction and the endpoints), J2 (the Issues page), J3 (search) and J4 (correcting the text and the contents).

| File | What it does |
|---|---|
| `index.php`, `issues-app.js`, `issues.css`, `header.php` | **The Issues page**: the issues newest first with a filter, the open issue's description, the state of its text (it asks again every two seconds while the text is being read), *Read the text again*, *Open the PDF*, a two-click *Remove*, and *New issue* (from a PDF in the file store, or an external address only). A regular user's status and access boxes are disabled; for an administrator the page asks for the PDF's direct address without credentials and **warns when it answers 200** (a site without the nginx gate). It uses the file editor module's stylesheet. |
| `source_list.php` | The PDFs of the file store a new issue can be made from, read from the file browser's catalogue (a PDF uploaded in the Files page is there), by part of a name or folder. |
| `search_lib.php`, `issue_search.php` | **Search**: a query is words, "a phrase", a prefix\*, and -excluded; it is folded like the pages (Bjorg finds Björg, Thor finds Þór, Saunderson finds Saunderson’s) and only the folded words reach the SQL, as bound values. The full-text index is used to narrow by the required words **only when it is safe** (no word shorter than `innodb_ft_min_token_size`, none on the server's stopword list), and every phrase and exclusion is checked with `LIKE`; otherwise `LIKE` alone. Results are pages (issue, date, page) newest first with a snippet of at most 30 words in the page's own spelling (HTML escaped, matches in `<mark>`); a page of an issue the viewer may not read has no snippet. `issue_search.php` is for signed-in editors (drafts included). |
| `public.php` | **A library for a site's own public pages**: `ips_issues_public_search($config, $q, $opts)`, `ips_issues_public_list($config)`, `ips_issues_public_find($config, $id)`; it reads the IPS's database settings from `php/classes/config.php` and returns only published issues. |
| `issue_page.php`, `issue_page_save.php` | **Correcting a page**: read a page (the text read from the PDF, and the correction if there is one) and save a correction or take it away (`restore=1`). The text read from the PDF is **never overwritten**; what is shown and searched becomes the correction (and its folded form, `search_text`); text equal to the original clears a correction. Any signed-in user may correct a draft; only an administrator a published or private issue. The Issues page's *Correct the text* opens the PDF page beside its text, moves between pages (an unsaved change is not left without asking: save, or discard), shows the original on request and restores it with two clicks. |
| `issue_toc_save.php` | **Contents**: replaces an issue's list of entries (kind, title, first and last page, author), checked whole (a title; pages inside the issue; the last not before the first; a kind from the list: article, front-page, letter, notice, obituary, advertisement, other), so a refused list changes nothing. Same rule for who may. The list is edited on the Issues page, in order, with *open* links to the pages. |
| `schema.sql` | `issues`, `issue_pages` (raw, corrected and accent-folded text, with a FULLTEXT index) and `issue_toc`. Run it once. No foreign keys; the code keeps the three together. |
| `lib.php` | Who may do what, the checks on a form, the PDF store (a copy named by its SHA-256 in `upload/archives/issues/xx/`), the queries. |
| `issue_create.php` | Makes an issue from a PDF already in the file store (`path=files/A/b.pdf`, copied; the same file twice is stored once) or, with no path, from an external address only (an issue hosted elsewhere, such as timarit.is). A draft, for signed-in readers. |
| `issue_save.php`, `issue_remove.php`, `issue_extract.php` | Change an issue's description, remove it (its PDF too when no other issue uses the file), read its text again (a correction is kept). |
| `issue_get.php`, `issue_list.php` | Read: one issue with how much of its text was read; every issue, newest first (an undated one last). |
| `file.php` | The PDF, by `id`, with byte ranges, an ETag and `nosniff`; allowed by `ips_access_can_read()`. A visitor who may not read it gets 404 (a draft's existence is not told). |
| `extract.php` | `pdfinfo` and `pdftotext` as fixed commands with no shell, a time and a size limit; judges a run of pages (`done`, or `no-text` for a scan). |
| `../php/issue_worker.php` | The background worker (CLI only), started by the endpoints, reporting through the issue's `extraction` state (`pending`, `running`, `done`, `no-text`, `failed`, with a note). |
| `../php/text_fold.php`, `../php/access.php`, `../php/iso_date.php` | Folding for search (Þ, ð, æ, ö, accents, soft-hyphen joins, symbol-font bullets, curly quotes), the one access function a subscription system would replace, and ISO 8601 dates. |

**Who may do what** (Ryan, 2026-10-30): any signed-in user makes an issue and edits a draft; only an administrator sets `published` or `private`, sets the access, or edits or removes a published issue; the maker of a draft may remove it. **Access:** `open` (anyone, once published) or `signed-in`; a draft or private issue is for signed-in editors only.

**Needs:** `poppler-utils` on the host (`pdfinfo`, `pdftotext`; `php_extra_packages`), PHP `mbstring`, `exec` allowed (as for the folder zip), and the DDL applied by the site's administrator. **The nginx gate must be deployed** (the three IPS sites have it): it is what keeps the direct address of a PDF under `upload/archives/` from visitors; a site without it must not hold a restricted issue (the base's own dev stack has no gate). Settings in `php/site-config.php`: `IPS_ISSUES_MAX_BYTES` (200 MB), `IPS_ISSUES_MAX_PAGES` (400), `IPS_ISSUES_EXTRACT_TIMEOUT` (180 s).

Tests (fleet repository): `tests/test_issues_logic.py` (folding, access and extraction in real PHP on LaTeX-made PDFs), `tests/test_issues_module.py` (the endpoints, the worker and the PDF's address on the mssdocs dev stack), `tests/test_issues_gate.py` (the direct address behind the gate, on the vesturheimsrit base stack) and `tests/test_ui_issues.py` (the page in Chrome on both stacks: the warning appears where the gate is missing and not where it is deployed; and the correction screen, the unsaved-change guard, restore, the contents, and a published issue locked for a regular user), `tests/test_issues_pages_logic.py` (the contents checks in real PHP), `tests/test_issues_search_logic.py` (query reading, engine choice and snippets in real PHP) and `tests/test_issues_search.py` (the search on the dev database, including a private corpus of three real L-H issues, skipped when they are not on the machine; `ISSUES_SPEED=1` adds a timing run on 20,000 synthetic pages).
